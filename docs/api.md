# API and numerical scope

`Emeans(k, nepochs=3, batch_size=None, alpha0=None, batch_law=BatchLaw.AUTO, unused_threshold=None, seed=1234)` clusters finite Euclidean FP32 vectors. `BatchLaw` is an enum with AUTO, QUALITY and THROUGHPUT values. String values are also accepted.

`train(x, init_centroids=None)` allocates and runs once. `prepare(x, init_centroids=None, orders=None, capture=False)` allocates a reusable workload; `run()` resets and trains it. CUDA graph preparation performs a warmup followed by capture. Graph replay includes initialization, shuffling, assignment, EMA, revival and finalization. It excludes preparation/validation/capture. Inputs and initial centers are retained; keep their storage and contents valid and finite until the next preparation. Returned arrays are overwritten by subsequent runs. CPU uses the scalar distance kernel; GPU distributes each point's centroid search over 32 threads. Both choose the lowest centroid index on exact ties. CUDA centroids use a strided view so neighboring search lanes read contiguous centers; consumers must honor Warp array strides.

`assign(x)` returns squared Euclidean distances and nearest-final-center labels. Training labels instead refer to the moving centers in the last pass. For budgets below one pass, unvisited rows have label -1; otherwise the final pass is full. Last-pass means use those recorded assignments, without another assignment sweep.

The resolved immutable `recipe` gives batch size, initial alpha, epoch row counts and revival threshold. Automatic policies match the pinned upstream source: quality at d<=16, throughput otherwise; revival off at d<=2 and threshold 0.1 otherwise. The cosine floor is 0.1, initial mass 2^-16, split perturbation 1e-4. Every fifth batch performs proportional sampling without replacement among live donors, splitting up to min(dead,live) clusters. Zero donors get a distinct smallest-positive-FP32 child, as in upstream; squared distances can still tie.

Warp RNG, direct squared-distance arithmetic, and atomic accumulation ordering differ from upstream NumPy/PyTorch. Shared-order, no-revival tests match upstream within FP32 tolerances. Revival is tested separately for donor uniqueness, count conservation, perturbation and graph replay. Equal seeds do not imply identical centroids across implementations. FP32 arithmetic can overflow for extreme coordinate magnitudes; use a common scalar rescaling when appropriate. Per-coordinate whitening changes the clustering objective and is not performed automatically.

The implementation supports Euclidean single-device FP32 clustering, not spherical clustering, quantization, distributed training, slow-EMA finalization, or differentiable training. Arrays requesting gradients are rejected explicitly. GPU input validation synchronizes once during preparation and each public assign; the batch loop performs no host readback. Optional explicit permutations are a testing facility validated once on the host.

Prepared `run(alpha0=value)` changes the initial step for that and subsequent runs without rebuilding the graph; the resolved recipe is updated. This is useful for controlled hyperparameter sweeps with fixed data, initialization and random stream. The training state is reset for each run. A later `prepare` resolves the constructor settings again.
